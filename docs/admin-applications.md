# 관리자 가입 신청과 운영자 승인

교수·교원 등 프로젝트를 관리하는 사람은 **증명서 PDF와 함께 신청**하고, **운영자가 직접 확인해 승인**해야 관리자가 된다.
이 문서는 `admin-governance-integration.md`의 "관리자는 운영자가 SQL로만 지정" 방식을 대체·보완한다(가입 정보로 관리자 권한을 얻을 수 없다는 원칙은 그대로다).

## 흐름

1. 로그인 화면의 **관리자 가입** 탭에서 계정 정보(이름·이메일·비밀번호)와 함께 소속·직위·연락처·증명서 종류·**증명서 PDF**·개인정보 동의를 **한 번에** 입력하고 가입한다.
2. 이메일 인증을 **끈** 설정(현재 운영 DB)이면 가입과 동시에 로그인되어, 신청서가 **자동으로 제출**되고 "검토 대기" 화면이 열린다.
   - 가입 직후 화면이 다시 그려지므로 입력 내용은 메모리에만 잠시 맡겨 두었다가 신청서 화면(`/admin-application`)에서 제출한다. 어디에도 저장되지 않으며 새로고침하면 사라진다.
   - 제출이 실패하면 오류를 보여 주고 입력값(파일 포함)을 채워 둔 채 다시 제출할 수 있게 한다.
3. 이메일 인증을 **켠** 설정이면 가입 직후에는 로그인할 수 없으므로, 인증 후 첫 로그인할 때 열리는 신청서 화면에서 같은 항목을 제출한다(코드 변경 없이 자동으로 이 방식으로 바뀐다).
4. 운영자가 **메인 화면 왼쪽 메뉴의 "운영자"**(대기 중인 신청 수가 배지로 보인다)에서 증명서를 열어 확인하고 승인 또는 반려한다. 프로젝트를 선택하지 않아도 열리며, 프로젝트가 하나도 없는 운영자에게는 관리자 화면 위쪽에 같은 영역이 보인다. 반려는 사유가 필수다.
5. 승인하면 그 즉시 관리자가 된다. 승인 전에는 일반 사용자로 계속 쓸 수 있고, 홈에 "검토 중" 배너가 보인다.
6. 반려되면 24시간 뒤부터 다시 신청할 수 있다(신청서 화면에서 재제출).

## 운영자 지정 (DB 소유자가 SQL Editor에서만)

운영자가 될 사람이 **일반 회원가입으로 계정을 먼저 만든 뒤**, 계정 UUID를 확인해 실행한다.

```sql
update public.profiles set is_operator = true, is_admin = true where id = '<운영자 계정 UUID>';
```

- 운영자는 앱에서 만들거나 해제할 수 없다(트리거가 막는다). 여러 명을 지정할 수 있다.
- 운영자에게 `is_admin`을 함께 주면 프로젝트 승인·삭제 등 관리자 기능도 쓴다.

## 증명서 PDF 취급

- 저장소 `admin-verification`은 **비공개**이고 PDF만, 10MB까지 받는다. 본인 폴더(`<user_id>/<uuid>.pdf`)에만 올릴 수 있고 사용자당 최대 5개다.
- 조회는 **본인과 운영자만** 가능하다. 운영자는 60초짜리 임시 링크로만 연다.
- **심사가 끝나면(승인·반려) 원본을 삭제**한다. 운영자가 관리자 화면을 열 때 삭제가 진행되고, 실패한 건은 다음에 열 때 다시 시도한다. 신청·처리 기록은 파일 없이 남는다.
- 제출 화면에서 "주민등록번호 등 확인에 필요 없는 정보는 가려서 제출"하도록 안내하고, 개인정보 수집·이용 동의를 받는다. 동의 문구는 실제 개인정보 처리방침에 맞춰 검토해야 한다.
- 제출 시 서버가 파일 존재·`application/pdf`·크기를 확인한다. 파일 내용 자체는 검증하지 않으므로 운영자가 직접 열어 확인하는 절차가 검증의 핵심이다.

## 관리자 해제

운영자만 관리자 화면에서 해제한다(본인·다른 운영자는 불가). 승인 대기 프로젝트를 맡은 관리자는 처리할 사람이 없어지므로 해제할 수 없다.

## 적용 순서(기존 DB)

1. `supabase/migrations/20260921180000_admin_applications.sql`을 SQL Editor에서 한 번 실행한다(부팀장 마이그레이션 `20260921170000`이 먼저 적용되어 있어야 한다).
2. `supabase/verify_runtime.sql`을 실행해 모든 행이 `ready = true`인지 확인한다.
3. 운영자 계정을 위 SQL로 지정한다.
4. **이메일 인증(Confirm email)** 설정을 확인한다. 현재 운영 DB는 꺼져 있고, 이 경우 가짜 이메일로도 가입되며 Supabase가 이메일을 자동으로 "인증됨" 처리한다. 그래서 운영자 화면의 "이메일 인증됨" 배지는 기본으로 **숨겨져** 있다(`src/lib/adminApplication.ts`의 `SHOW_EMAIL_VERIFICATION_BADGE`). 이메일 인증을 켜고 운영한다면 이 값을 `true`로 바꾼다. 어느 쪽이든 승인은 운영자가 연락처와 증명서로 직접 확인하는 것이 기준이다.
5. 프런트엔드를 배포한다. 마이그레이션 전에 배포해도 앱은 멈추지 않는다(운영자 확인은 실패 시 "운영자 아님", 신청 배너는 조용히 숨김).

## 감사 기록

`admin_applications`(처리자·처리 시각·사유)와 `admin_audit_log`(승인·반려·해제)에 남는다. 운영자만 조회한다.
