# coffe 관리자 기능 통합

2026-09-18. `coffe`의 `235805f`를 현재 main의 평가·채팅·워크스페이스 구조에 맞춰 통합했다.

## 포함한 기능

- 관리자 전용 프로젝트 승인/반려, 전체 프로젝트 목록 및 삭제, 외부 프로젝트 팀원 조회/제외.
- 생성 시 날짜와 승인 담당 관리자 지정. 기존 프로젝트는 승인 상태를 유지하고 신규 일반 사용자 프로젝트는 승인 대기로 생성.
- 승인 대기/반려 프로젝트의 화면 접근 제한과 주요 데이터 쓰기·Storage 업로드의 서버 측 제한.
- 팀장/관리자 종료 버튼. 기존 `complete_evaluation_project` RPC를 사용하고 서버에서 `completed_at` 기록.
- 일정 제목·날짜·유형·공개 범위 수정 및 삭제. 본인 개인 일정과 팀장의 팀 일정만 변경 가능.
- 관리자 소속 필드, 요청 실패 표시 및 중복 요청 방지.

## 기존 main과 맞춘 부분

- 워크스페이스 원본·버전·태그·댓글·검색 및 최근 활동을 유지.
- 평가 점수의 본인 열람 제한을 유지. 관리자 팀원 조회는 별도 RPC를 사용하며 평가 점수를 반환하지 않음.
- 가입 폼에서 관리자를 선택하는 기능은 제외. 가입 메타데이터의 `is_admin`은 무시하고 관리자는 운영자가 지정.
- 일반 팀원에게 members UPDATE 권한을 주는 정책은 제외.
- 평가 기록/제출 기록이 있는 팀원은 강퇴하지 않음. 기록을 연쇄 삭제해 점수와 익명성 조건을 바꾸지 않기 위함. 종료 프로젝트에서도 강퇴 불가.
- 종료 후 30일 자동 보관·삭제 작업은 새로 설치하지 않음. 기존 시스템에 같은 작업이 있다면 그 운영 정책은 별도로 확인해야 함.
- 기존 coffe의 정리 함수가 존재하면 public/anon/authenticated 실행 권한을 회수. 평가 이력 테이블 자체나 기존 운영 작업은 삭제하지 않음.
- 프로젝트 삭제 시 원본 정리 큐가 남도록 보강. 관리자 화면의 원본 파일 정리 재시도로 네트워크 오류 이후에도 정리 가능.

## 적용

기존 DB에는 최신 main 마이그레이션들이 적용된 상태에서 `supabase/migration_admin_governance.sql`을 적용한 후 프런트엔드를 배포한다. 신규 DB는 `supabase/schema.sql`에 통합되어 있다. 통합 작업 중 운영 DB에는 SQL을 실행하지 않았다.

이 마이그레이션은 이전 coffe 마이그레이션 6개를 대신한다. 이전 파일을 추가로 실행하면 권한 정책이 되돌아갈 수 있으므로 실행하지 않는다.

최초 관리자 지정은 운영자의 SQL Editor에서 실제 계정 UUID를 확인한 뒤 수행한다.

```sql
update public.profiles set is_admin = true, org = '소속'
where id = '<확인한 계정 UUID>'::uuid;
```

예전에 관리자 셀프 가입 기능을 운영했다면 기존 관리자 계정 목록은 운영자가 검토해야 한다. 이 마이그레이션은 기존 관리자 권한을 일괄 회수하지 않는다.

## 검증

- TypeScript 검사 및 Vite 프로덕션 빌드.
- `tests/admin-governance.test.mjs`: 전체 스키마 설치·반복 마이그레이션, 가입 메타데이터 공격, 직접 승격/승인 우회, 지정 관리자 승인, 구성원 열람·제외, 일정 소유권, 종료 저장·재실행, 원본 정리 큐와 삭제 권한.
- 기존 평가·평가 개인정보·워크스페이스 버전·댓글·검색·최근 활동 회귀 테스트.

DB 검증은 PGlite로 수행한다. 실제 Supabase/Vercel 운영 환경 적용은 별도다.
